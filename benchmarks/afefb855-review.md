## 已确认并修复

1. 无效页面消息进入 catch 后再次读取 `m.type`，造成新的 Promise 拒绝。聊天、侧栏和通知面板现在先验证消息形状，错误只记录安全类别，后续有效消息仍可执行。
2. CLI stderr 将 HTTP 403 验证页拆成多个异常，且保存 HTML/脚本片段。现在只记录状态、响应类别和已证实的 MCP 传输类别；续行合并有 2 秒、8 行、16 KiB 上限，不吞掉后续独立异常。孤立 HTML 保留脱敏警告。历史扫描也严格按版本、窗口、进程和邻近时间关联正文，不另算插件脚本故障。
3. 工作线程异常跨进程传递时丢失错误码和失败标识。现在权限错误、异常退出、超时、取消和成功都在统一边界结算，worker 与 execute 共享失败链；不传递错误正文。
4. 本地发送配置校验、等待问题持久化，以及暂停/停止确认截止只有界面报错或关闭结果。现在补齐安全失败类别、阶段、进程与轮次标识，确认超时明确为 timeout 来源。
5. 通知聚焦的真实 2 秒截止原来只显示 unknown/Error。现在记录 `ETIMEDOUT`、阶段与阈值，仅将失败之后开始的真实成功聚焦关联为恢复；并发在途成功不会错误抵扣稍后失败。没有放宽确认条件或自动重试。
6. Webhook HTTP 200 业务拒绝缺少安全业务码和阶段。现在开始与唯一终态共享 operationId，区分配置、请求、响应解析、业务响应；保留原有业务成功判断。没有实际发送通知。
7. 高亮器错误虽能回退正文，但缺少可检出的降级记录。现在限流报告白名单错误类型，宿主按 fallback 警告记录，正文转义与后续成功渲染保持正常。
8. 诊断页面把 runtime 与 unhandledrejection 均压成通用 Error。现在保留固定阶段和错误类型。外链失败日志移除完整 URL；日历更新/缓存失败改为结构化脱敏日志，并为后续恢复保留关联标识。
9. 修复会话在完整问题清单后又重复附加报告前 60,000 字符。长报告已有完整落盘路径时不再重复粘贴，保留所有 86 个问题的证据、建议，以及读取全部源码覆盖位置的明确要求。没有完整文件路径时仍保留原有正文回退。
