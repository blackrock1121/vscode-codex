# 远程接入的隔离和兼容约定

适用于插件 0.1.153 起的 v1 接口。手机仍通过独立 Mac 远程服务调用插件的原 Codex 会话。

## 代码边界

- `src/remote/sessionAdapter.ts` 负责远程命令、手机等待队列、历史分页、图片读取、输出事件与审批版本。状态保存在适配模块的 WeakMap 中，不混入电脑聊天上下文。
- `src/remote/host.ts` 是接入层可调用的宿主接口。适配模块不导入 VS Code 或 ChatViewProvider；宿主显式提供发送、停止、历史、配置和还原等能力。
- 电脑界面的消息发送和排队保持原路径。手机队列暂由独立适配模块调度，以保留已有队列的确认、原会话互斥和历史版本兼容；不与电脑输入队列合并。
- 网络、配对、加密和手机完成通知在 `vscode-codex-remote` 项目。插件只发送有界事件，不等待手机网络或通知发送。
- 手机访问过的私人会话标记仍由宿主持久保存。关闭远程不恢复旧 Webhook 正文推送。

## 独立升级

注册和命令继续使用 `version: 1`，不要求 App、桥接和插件版本号相同。`contract.ts` 定义可选能力；跨仓库集成测试核对两边合同。

| 能力 | 操作 |
| --- | --- |
| chat | 会话列表、历史、文字发送、新会话、停止 |
| controls | 设置、问答、审批、工具与文件变更详情 |
| attachments | 图片上传后发送 |
| actions | 改名、置顶、删除、压缩、消息编辑与重新生成 |
| images | 历史图片分块读取 |
| queue | 手机入队、查询、移除与继续 |
| stream | 实时输出快照；主动推送还要求桥接握手的 `features.events` |

新增注册字段和能力必须可选；新增操作应有能力检查，不能直接发给未知版本。基础命令的字段、错误码和含义保持兼容；破坏性修改需要新协议版本及并行迁移，不能直接重定义 v1。

新桥接遇到不声明能力的旧插件，先按只读快照探测；没有能力声明就保留基础文字聊天。旧插件快照的 `controls` 按历史含义兼容问答和上传。不支持的操作返回 `UNSUPPORTED_FEATURE`，不调用插件，不自动重发。

新插件遇到不声明事件支持的旧桥接，只返回请求回执，不推送旧桥接不认识的事件；历史仍可主动读取。未知操作或非法业务参数只拒绝本次请求。认证失败、伪造目标、非法传输帧仍断开连接。

## 故障边界

远程发布、序列化或事件监听器失败，不得阻断电脑输出、结束处理或其他远程订阅。保留有界日志；流量和帧大小仍受限制。已交付但回执未知的写操作保持“结果未知”，不能以重试制造重复任务。

设置 `codexChat.remoteEnabled=false` 可即时关闭远程接入并停止手机队列后续派发。已开始的 Codex 任务继续执行，电脑聊天照常使用；需要时在电脑停止。重新开启后可在手机查看并继续队列。

两端仍共享插件执行核心。VS Code 退出、插件无法启动或 Codex 核心故障会影响远程；这里隔离的是接口升级、远程附加功能和错误传播，不承诺两套独立执行环境。

## 发布验证和回退

插件 `npm run check-types`、`npm test` 必须通过。测试包含旧桥接 `6fa2a53` 的冻结实际实现、新插件与旧桥接互通、未知操作后继续聊天、关闭远程后的电脑发送、异常通知隔离。

远程项目的测试包含插件 `1b370b5`（0.1.151）的冻结实际传输和命令解析实现，新桥接与旧插件互通，并检查通知监听器的同步异常和异步拒绝。历史样本不随当前代码自动生成或更新，变更需明确验证迁移理由。

两端构建后执行远程项目的 `node scripts/test_plugin_bridge.mjs /path/to/vscode-codex`，验证真实 Unix socket、加密命令和原会话发送路径。测试使用假 Codex 进程，不消耗模型额度，也不替代真实手机验收。

每次插件发布保留上一个 VSIX；桥接可回退到上一个已提交版本后重新构建。回退不删除配对密钥、设备授权、聊天历史或手机缓存，不自动重放断线前命令。

## 0.1.154：桥接持久队列与交接核对

新版桥接 0.1.2 保存并调度手机队列；插件仅接收原会话 message.send，使用工作区状态记录命令 ID、摘要和交接状态，不保存正文。新增 command.status 只读核对接口，能力 receipts 显式声明。未知记录不能自动再次执行。旧桥接继续使用独立适配器的原内存队列接口，升级前应先处理其中的旧任务。

返回值和事件合同位于 src/remote/results.ts。新桥接注册回执声明 features.unknownResults 时，发送异常返回 PLUGIN_RESULT_UNKNOWN，仅标记当前请求未知；旧桥接仍使用断开连接的保守语义。

兼容测试新增上一正式桥接 0.1.1 的冻结样本；全链路发布门禁由远程仓库 npm run release:check 执行，包含本仓库类型检查/测试、双方实际 IPC 和 Android 新旧组合。接口兼容以行为为准，不要求两仓库文件逐字一致。
