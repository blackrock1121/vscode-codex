# Codex Copilot

基于 `claude-chat-main` 的 Copilot 风格 VS Code 编程助手。界面与交互复用原项目，底层重写为本机 **Codex app-server**，复用 Codex 自己的登录与账号能力。

QQ 机器人、SLS 日志查询已移除。不发送主动缓存预热消息；打开已有会话时只提前建立连接并恢复会话。

## 手机原会话接入（0.1.120）

本机 Mac 的可信任文件工作区可连接配套 `vscode-codex-remote` 桥接。插件仅通过 `~/.codex-chat/remote-bridge/bridge.sock` 私有 Unix socket 注册窗口；检查同用户所有权、0700 目录、0600 socket/令牌文件，不自行开放公网端口。手机端仍须在 Mac 明确获得项目授权。

APK 0.0.6 可选择当前窗口已打开/后台运行的会话，发送文字、新建会话、停止轮次和分页读取记录。发送复用原 provider 与原会话进程，窗口/工作区/会话目标固定；准备阶段两端互斥，断线/过期不自动重放。手机发送的用户消息同时进入桌面显示，桌面草稿不被清空。读取快照时原会话历史经现有 SessionStore 获取，当前不是逐 token 推送。

手机接管的会话会持久标记为私人会话，后续任务内容不再发向旧 Webhook，本机通知保留。其他未接管会话仍使用原通知设置，已有第三方历史不会删除。当前未开放手机问题回答/审批、图片上传或差异视图；等待输入时暂在电脑处理。ECS 部署和真实手机公网验收由配套项目完成，此版本本身不代表公网已启用。

## 速度模式与额度

输入框下方并列显示模型、推理强度和快速模式闪电按钮（灰暗空心为普通，亮起实心为快速）。开关只在保存成功后更新状态，鼠标悬停可查看当前模式、生成速度说明和额度消耗；快速档位不可用时不能开启，但始终可以关闭。推理入口直接显示当前档位（如「中」），窄面板也保留文字，可直接打开选择其他档位。模型菜单只列模型。

模型、速度和推理强度按会话独立保存，仅对当前会话的下一轮生效，关闭重开或重载窗口后仍会恢复，不影响其他可见或后台会话。新会话分别使用 `codexChat.model`、`codexChat.speedMode` 和 `codexChat.effort` 的默认值；在会话中切换模型不会修改公共默认值，也只会重置当前会话不兼容的推理档位。推理默认 `medium`（均衡），简单任务可选 `low`，复杂分析可选 `high`。派生会话继承原会话设置，之后各自独立。保存失败会保留原设置。普通模式明确请求普通档位。

一个会话保存设置时，其他会话仍可独立调整和发送消息。发送消息或提交问题答案会等待本会话的设置保存完成；重连、清空和还原派生也会按顺序处理，避免旧值覆盖刚确认的选择。

依据 [OpenAI 官方速度说明](https://learn.chatgpt.com/docs/agent-configuration/speed)和[额度说明](https://learn.chatgpt.com/docs/pricing)（2026-10-14 核对）：

| 模式 | 生成速度 | ChatGPT 订阅内额度 | 官方支持说明 |
| --- | --- | --- | --- |
| 普通 | 1× | 1× | 基准速度 |
| 快速 | GPT-5.6／GPT-5.5 为 1.5×；GPT-6 系列具体倍率未公布 | 2.5× | 支持的 GPT-6 Astra、GPT-6 Sol、GPT-6 Luna、GPT-6.1 Sol 等；以账号实际开放为准 |

生成速度不代表整个任务的提速倍率。API 密钥按模型及服务档位另行定价，不套用 ChatGPT 订阅额度倍率；[官方 API 快速模式说明](https://developers.openai.com/api/docs/guides/fast-mode)公布 GPT-5.6 Sol 最高 2.5× 的 API 提速。购买额度和企业按量计费也不同于订阅内额度，具体以官方说明及协议为准。未来或未知模型不自动套用上述倍率。

可选档位以当前 Codex `model/list` 返回的 `serviceTiers` 为准，兼容旧版 `additionalSpeedTiers`。即使模型名称相同，不同账号的套餐、工作区及地区也可能不同；未提供或无法确认的加速档位会置灰，后端再次检查，绝不自动升级、降级速度或更换模型。切换到不支持原加速档位的模型后，请手动选择可用档位。默认模型的速度能力依据已连接会话实际模型确认；未连接时请先选择具体模型，不使用目录的默认标记猜测本机配置。

设置项为 `codexChat.speedMode`（`default`／`fast`）。尚未设置新选项时兼容 0.1.21 的 `codexChat.fastMode`；显式选择普通模式后不会被旧的 `true` 值覆盖。旧版保存的超高速档位会恢复为普通，避免开关未显示对应档位时继续产生更高倍率消耗。需使用支持服务档位协议的 Codex CLI（已验证 0.156.1）。

## 执行调度与失败处理

`codexChat.executionMode` 默认 `parallel`，适用于插件后续新建和重新连接的会话，不修改会话已选模型、推理强度、收费档位或执行权限，也不重启正在执行的任务：

- `parallel`：独立读取、搜索和检查批量执行；有足够独立工作时主动委派最多 2 个子 Agent，主 Agent 同时推进其他工作。子 Agent 可能增加总额度消耗；简单任务不拆分，写入范围或资源冲突的工作按顺序执行。
- `tools`：保留工具批处理和失败处理策略；子 Agent 按用户或项目指令使用。
- `standard`：不追加插件的效率指令，使用原生调度策略。

效率指令要求先收取前置检查的最终结果再启动依赖构建，按需确认依赖及服务就绪状态，区分临时网络错误、环境问题与代码错误；同类失败再次发生时先诊断，避免原样重跑和无理由重复全套验证。这是对模型的执行指导，不会拦截或改写 Bash 命令，也不能保证消除业务错误或按固定倍数提速。原生工具并发本来由 Codex 提供，不存在一个能把有依赖的任务全部并行的插件开关。

子 Agent 的工具与审批只在后端父子关系及共享会话标识校验通过后接入，并显示来源；多个审批依次展示，答案返回原子任务。停止时同时停止根任务及已确认的活动子任务。原生阻塞问题支持文字回答；子任务异步问题尚不支持直接恢复，会明确提示并停止该子任务，由主任务重新提问，避免把答案续到错误会话。长命令的真实输出与子任务活动按秒合并更新进展，不保存输出正文到诊断日志，避免持续工作的命令被误判为长期静默。

本次并行协议核验使用 Codex CLI **0.162.1**；更旧版本可能缺少父子线程元数据。配置及能力依据：[官方子 Agent 说明](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[App Server 协议](https://learn.chatgpt.com/docs/app-server)。

## 插件诊断中心

默认开启 `codexChat.transportDiagnostics`，重载后新连接会自动采集，日志保存在 `~/.codex-chat/logs/`，按天分文件并保留最近 7 天。点击输入框权限按钮旁的虫子图标，或运行 **Codex: 打开插件诊断中心**，立即打开独立页面，查看历史诊断记录并按编号、项目或版本搜索；**Codex: 打开日志文件夹** 可打开原始结构化日志。

默认诊断范围是**本机整个插件**，跨工作区、窗口、会话和插件版本，不按发起位置过滤。页面默认“全面诊断 / 最近 24 小时”，也可选择“速度诊断”、最近 7 天或全部保留日志。点击“开始诊断”后，独立工作线程逐行扫描日志快照，检查选定滚动区间的结构化事件和普通报错、警告、重试、恢复记录。全面诊断覆盖压缩请求/配置恢复/转发、连接与 CLI 进程、页面脚本、快照与还原点、会话恢复、通知、工具及性能异常。记录按类别归并，保留出现次数、脱敏示例、文件行号、时间、版本和窗口；时间缺失的记录不冒充最近 24 小时，会单列缺口。

页面支持选择“模型诊断 + 本地检查”或“仅本地规则检查”。模型及 `reasoning effort` 来自当前 Codex 账号的模型目录，使用官方英文值，例如 `medium`、`high`、`xhigh`；设置单独保存，不改聊天会话的模型和推理档位。模型模式使用独立临时 Codex 线程、普通服务档位，仅分析脱敏后的异常摘要和性能证据，不发送整份原始日志；会使用当前账号的模型额度。本地规则模式不调用模型、不消耗模型额度；保存为该模式后，打开和启动诊断也不会先连接 CLI 或等待模型目录。切换到模型模式或主动刷新时再加载目录，目录等待最多 10 秒并支持取消；迟到响应不会覆盖用户刚修改的设置。每条记录保存所选和实际采用的模型/推理、模型运行时长及成功或失败结果；后端替换所选模型时停止，不擅自降档。模型输出必须引用已有证据；失败、格式错误、超时或引用无效时保留本地检查结果，并明确标为“部分完成”。可停止诊断；关闭页面不会停止，窗口退出则中断。

扫描不限制文件数量和文件大小，区间内所有有效记录都参与本地汇总；报告保留有限的最慢项和异常示例，模型输入最多包含 60 组脱敏证据和 100 个版本/窗口来源，按异常类别、性能阶段和采集完整性轮流取证，避免高频工具错误挤掉压缩等低频故障；记录显示实际发送与仅本地保留的证据数量。压缩证据保留模型、推理、触发方式及 HTTP 状态；不同状态码或退出码不合并为同一问题。其余本地结果仍可查看。大量重复 stderr 错误/警告只记录每分钟最多 30 条脱敏摘要，达到上限也会留下缺口提示。诊断模型不执行修复；点击修复按钮才创建修复会话。连接准备、配置读取和模型生成均能取消；完成事件先于请求受理回执到达时可直接收取结果。页面合并短时间重复刷新，查看历史证据时保持展开状态。[调用方式依据官方 App Server 协议](https://learn.chatgpt.com/docs/app-server)。

关闭诊断页面后仍继续，进度与结果保存在 `~/.codex-chat/diagnostics/`。页面显示日志日期、实际采集时间、文件数、读取字节、记录数、可识别窗口/会话数和被分析的版本；按版本与窗口提供全量统计。发起位置仅表示在哪里点击诊断。旧版记录明确标记为“旧版全局采样”，不会冒充全量结果。窗口退出会终止本窗口的后台任务并标记中断，不会假报完成。

诊断完成后使用现有 `codexChat.notifyWebhook` 中的飞书机器人发送通知，包含诊断编号、项目、插件版本和问题数，不包含完整日志或报告。此通知不受普通任务最短通知时长和静默时段限制；未配置、发送超时或飞书返回错误均在对应记录显示，可点击“飞书通知设置”配置，再重试通知。打开页面查看记录不会触发新诊断或重复通知。

收到通知后按编号找到记录，点击“创建修复会话”，会在当前工作区新建会话并自动发送全局诊断问题及证据，不要求回到诊断发起位置；修复目标明确为插件源码，会先验证源码位置与根因，不修改无关业务项目。已有修复会话的记录显示“查看修复会话”，在该修复会话所在工作区打开，跨窗口重复点击不会重复创建。旧版记录保留原有工作区绑定。当前规则检查覆盖失败分类、准备/工具/压缩耗时、未归因等待、潜在串行调用、重复命令、子 Agent 尾部等待、采集缺失和宿主延迟；这些是待核验线索，不能仅凭耗时断言调度或模型有问题，也不会擅自更改模型、推理强度和权限。原有会话与草稿保持原状。

- `[perf]`：通过 `traceId` 关联排队、发送准备（前轮收尾、附件、自动保存、历史、快照、连接、设置）、当前线程/轮次、工具与 Bash 起止、首次输出、输出静默、退出码、失败分类、子 Agent 启动与尾部等待、用户审批/回答、最终快照整理。每 30 秒记录活动阶段、扩展宿主内存/CPU、事件循环延迟、RPC 解码/处理耗时与写入背压；CPU/内存属于整个扩展宿主，不能直接当作本插件独占资源。
- `[transport]`：记录 CLI 实际提供的请求、首 token、后端 engine timing、工具执行/审批及重试指标。事件按源时间和线程/轮次关联，延迟上报不归给下一轮；缺少关联字段则保留 `traceId: null`，进程级 histogram 不强行分摊到某轮。
- `[compaction]`：保留手动/自动压缩、实际压缩模型、配置同步/恢复、请求受理、后端事件、用量和失败记录，并接入同一任务标识。

`turn_summary.phasesMs` 为互斥墙钟分类，优先级为用户等待、压缩、工具、本地准备、可见模型输出、子任务尾部等待、显式子任务等待、未归因。`kinds.*.totalMs` 是可重叠的阶段累计时长，不能相加当作任务耗时；子任务尾部等待也可能与工具阶段重叠。报告中的可见模型输出阶段不等于纯推理时间，未归因等待不等于服务端排队。后端未给出的网络、服务端排队等细分保持未知。

Bash 只记录进程内加盐的命令指纹、有限程序类别、退出码和失败分类，不写完整命令、路径、参数或输出。重复命令是诊断线索，不自动视为重试；`rg`/`grep` 的纯搜索无匹配退出码不计为失败。工具被停止、缺少开始/结束事件或采集达到上限时明确标记不完整，不伪造成功或耗时。

每条日志都带插件加载时捕获的 `pluginVersion`、窗口加载实例 `windowId` 和宿主进程 `hostId`，多窗口共享日志时也能区分版本和来源；诊断报告显示每个任务的版本，旧日志缺少标识时明确显示未标注。

日志不随每个 token/输出片段落盘，每 200 毫秒批量异步追加，VS Code 输出通道也按批更新；创建目录、过期清理和写文件全部异步执行。缓冲上限 1 MiB、单行上限 32 KiB；触及上限或写入失败会记录丢弃数量。退出前排空缓冲，异常强制结束可能损失尚未落盘的尾部。诊断按扫描开始时各文件的长度快照读取，期间新追加的记录留到下次；文件读取失败、损坏行、异常超长行和缓冲丢弃均在结果中显示。全量范围限于本机实际保留和已采集的观测数据；不能恢复已删除或未采集的日志，不含其他机器/远程宿主，也不等同于自动审查所有源代码。本地规则不上传日志；模型模式只发送页面注明的脱敏摘要和证据，不上传整份原始日志。不保存提示词、图片、完整工具输出或凭据。

CLI 可提供的事件与指标依据：[官方 OpenTelemetry 配置](https://learn.chatgpt.com/docs/config-file/config-advanced#observability-and-telemetry)。不同 CLI/服务版本可提供的字段不同，新埋点不能追溯补全升级前没有采集的数据。

## 安装

要求 VS Code 1.90+，本机已安装 Codex CLI。当前协议与真实集成测试基于 **codex-cli 0.156.1**；旧版本可能缺少分页历史、指定轮次派生及删除接口，请先升级。

```bash
code --install-extension release/vscode-codex.vsix --force
```

也可在扩展面板选择“从 VSIX 安装”，选取 `release/vscode-codex.vsix`。安装后打开可信任的项目，点击活动栏 Codex 图标，新建会话。

- 已在本机 Codex 登录：直接复用。
- 未登录：命令面板运行 **Codex: 登录账号**，浏览器完成官方登录。
- CLI 找不到：配置 `codexChat.codexPath` 为可执行文件绝对路径。
- 账号详情：命令面板运行 **Codex: 查看账号状态**。

插件不读取或另存 OAuth 密钥，不把 ChatGPT 订阅转成 API Key。实际用量与可用模型由 Codex 和账号决定。SSH、容器和远程工作区需要在扩展运行所在环境安装、登录 Codex。

## 功能

- 连续任意两次工具调用即合并为一个默认折叠的工具组，不要求同类工具重复。Bash、网页检索、文件读写、技能及自定义工具交错调用时也合并，展开后按原顺序查看详情；正文、待回答问题和审批入口独立显示。实时消息和历史回放使用相同规则。

- 流式聊天、Markdown、代码高亮、可折叠思考、工具卡片及审批。
- 流式 Markdown 复用未变化的段落、图片和代码节点，长回复合并格式化更新，文字仍即时显示；未换行的代码、列表和表格保持结构。超过 30,000 字符的代码块保留全文、折叠和复制，跳过语法高亮，避免收尾时长时间卡顿。
- 隐藏标签暂停界面心跳检测，后台任务仍受停滞检测保护。关闭的会话空闲后定期回收超额进程，保留最近使用的五个；运行、等待回答、快照收尾、恢复和派生中的会话不会被回收。编辑重发、清空和重载历史同步释放旧消息的尺寸监听器。
- 多会话标签页、恢复历史、重命名、置顶、批量删除、重开关闭的标签。
- 动态模型列表、推理强度、权限模式、全局追加指令与项目 `AGENTS.md`。
- 文件选择和拖入、选中代码附加、图片粘贴、大图、复制和保存。
- 文件／行号／符号引用跳转，代码块复制和发送到终端。
- 随时停止、消息队列、编辑重发、最后一条回复重新生成。
- 聊天内容搜索、提问目录、长历史分段展示、草稿恢复及输入历史。
- 文件改动汇总、原生 diff、逐个或全部保留／回滚。
- 每轮还原点、对话回退、从历史节点派生独立会话。
- 重新生成提前准备派生连接，连接已退出时也收齐文件快照后再回滚；准备过程记录总耗时。并发会话列表刷新合并请求与界面渲染，失败后可重试。手动压缩在连接准备期间合并重复点击，空白会话不建连接，切换会话、替换进程或开始还原后取消旧压缩请求。
- “还原到此处”确认后提前准备派生连接，与历史读取、旧进程退出和快照收集并行；实际回滚仍在检查完成后执行。界面显示当前阶段，日志 `[restore]` 记录阶段及总耗时，失败或会话切换时释放预备连接。
- 点击派生立即显示加载提示，依次显示读取对话、创建会话、复制还原点、打开新页；期间防止重复点击，取消、失败或完成后恢复。原会话仍可继续回复，派生各阶段耗时写入本机日志 `[fork]`。
- 派生连接初始化与原会话历史校验并行，复用完整的派生响应和首次打开时的历史，减少重复读取。创建、恢复和读取会话均校验 ID；派生 ID 与已知会话或本地还原点冲突时中止，避免覆盖已有会话。
- 编辑后重新生成也与派生、还原互斥，并先读取最新历史确认回退位置。会话列表分页刷新保留期间更新的历史缓存；分页游标重复时终止并报错，避免无限读取。
- 已提交的问题卡支持“重新回答”：确认后撤回旧答案及之后的全部对话，同时回滚快照管理范围内的后续文件改动（包括后续轮次、已点击“保留”的改动），再展示问题卡等待新答案；原会话保留在历史中。缺少可验证快照的旧记录、关闭快照的轮次或无法还原的文件变更会阻止操作，不再降级为只回退对话。普通答案回填，私密答案重新填写。文件还原沿用工作区快照的排除规则，不撤销外部服务操作。
- 还原前先保存待回答的问题并检查文件；中途写盘失败会尝试恢复操作前的文件内容，保留还原点供重试。还原期间及失败后，排队消息不会自动发送；可从队列撤回后主动继续。
- 问题卡的自定义回答支持添加、粘贴或拖入图片，可预览、移除，也可仅用图片回答。图片按题目随答案一起提交，“重新回答”会回填原图；私密问题仍仅接受文字。支持 PNG、JPEG、WebP、GIF，一次回答最多 10 张、单张 10 MB、总量 20 MB。
- `/help`、`/clear`、`/compact`、`/model`、`/effort`、`/usage`。
- 订阅用量、服务端报告的上下文占用；没有报告时不猜模型容量。用量弹层列出 Codex 返回的可用重置卡和逐张有效期，临近到期的卡会高亮；后端只返回张数时明确标注有效期未返回。
- 连接预启动、后台连接保留、轮次超时检测、界面心跳恢复、本地日志。
- 首次发送优化：打开空白聊天时提前建立 Codex 连接、读取模型目录；真正发送且回滚快照完成后才创建会话。账号信息在后台读取，仅用于套餐与计费类型显示，不再阻塞会话创建或发送；实际鉴权仍由 Codex 执行。`codexChat.prespawnOnOpen` 可关闭打开时的提前连接。
- 清空聊天后也立即重新准备连接。多个标签页共用界面账号信息与完整模型目录的读取，成功结果最多缓存 30 秒；账号切换或连接断开时立即失效。发送前的加速档位校验继续使用当前聊天连接实际返回的目录。
- 可选 webhook 完成／等待输入通知，以及从本项目仓库检查更新。

配置项在设置中搜索 `codexChat`。快捷键：`Cmd/Ctrl+Shift+I` 聚焦输入；`Cmd/Ctrl+Shift+L` 添加选区；聊天内 `Cmd/Ctrl+F` 搜索。

## 飞书与本机通知

命令面板运行 **Codex: 任务推送配置**。飞书等 Webhook 是主要的远程提醒渠道：任务完成或停下来等待输入时，仍按原来的耗时阈值推送。远程连接公司 Mac 时，在家中的飞书也能继续收到提醒。

配置页支持重载窗口后自动恢复，并重新读取已经保存的设置；尚未保存的修改不会跨重载保留。保存或刷新日历失败时，页面会显示错误，方便重试。不支持本机通知的远程宿主不会暂停飞书推送，即使同步的设置中开启了本机通知和静默规则。静默时段内若本机通知报告发送失败，会立即补发该条飞书提醒。

新增 **同时开启本机通知（可选）**，默认关闭，与 Webhook 各自独立。本机通知关闭、没有系统权限或发送失败，都不会取消飞书推送。两种通知共用原有耗时阈值。

- 本机通知仅支持扩展运行在本机 macOS 的桌面 VS Code。通过屏幕共享控制公司 Mac 属于此场景；VS Code Remote SSH、容器和浏览器窗口暂不支持本机通知，继续使用 Webhook。
- 点“测试本机通知”验证权限与跳转；第一次需要允许 **Codex Copilot Notifications** 的系统通知。系统设置 → 通知中可以调整横幅、声音，专注模式可能隐藏通知。
- 从 0.1.38 或更早版本升级至 0.1.39 时，为修复系统持续显示默认图标的问题，通知辅助程序会迁移到新的应用标识，需要重新允许一次系统通知。后续版本保持该标识不变。
- 点击任务的本机通知，会回到发出通知的 VS Code 窗口，并选中对应 Codex 会话；关闭的会话标签会重新打开。窗口已关闭或重载时，旧通知可能失效，需要从会话历史手动进入。
- 点击仅用于打开会话，已有标签直接复用，不会自动回答、重发通知或清理该会话的新提醒；打开失败只提示，不自动循环重试。主动回复成功后的清理与通知点击独立，迟到的旧通知点击回调不会清掉新一轮提醒。
- 本机通知按真实会话 ID 只保留最新一条，完成／待回答／待授权会互相替换。关闭会话标签，或直接在会话中成功发消息、回答问题、处理审批后，会清理该会话的旧通知，无需点击通知；关闭前仍在排队的旧提醒也会失效，不同会话及派生会话各自独立。运行中关闭标签仍会继续后台执行，之后真正完成时会正常提醒。旧版积累的通知只在对应会话关闭、回复或产生新通知时清理，不在程序启动时批量整理其他会话；归属不明确的通知保留。飞书等 Webhook 的历史消息不受影响。
- AskUserQuestion 提交答案成功后立即请求清理本会话的待回答通知，同时清理 0.1.68 及之后历史安装路径里的同会话通知，升级后也不遗留。更早版本无法可靠识别会话的遗留通知需手动关闭一次；不会批量清空其他会话。日志记录 `question_answer` 清理请求、当前路径完成及历史路径的结果。
- 通知使用完整会话 ID，不按标题或 ID 前缀合并。「还原到此处」成功后清理旧会话通知并使排队中的旧提醒失效，新分支独立通知；还原到开头同样清理，取消或失败则保留原通知。派生和还原不能同时操作同一会话。
- 清理旧通知不等待跳转地址解析；同一窗口内复用每个会话已解析的地址，解析失败可重试。回复或还原后迟到的本机发送错误不会再补发旧飞书提醒；通知程序重启后也会检查已展示提醒的时间，拒绝用较旧的请求覆盖它。
- 本机任务通知采用紧凑内容：标题显示“工作区名称 · 状态”，正文显示耗时和一行摘要。已保存的工作区优先使用自定义名称；未保存的工作区使用目录名称，多个目录显示为 `game-server / funny-games`，超过两个时用 `+N` 标明其余目录数量；长目录名分别截短，保留两个目录的辨识信息；等待回答时不重复展示本轮提问，长文本以省略号结尾，点击可查看完整会话。
- 飞书通知横幅仍由飞书打开聊天消息；本机通知的开关不会修改这个行为。

原生通知辅助程序随 VSIX 附带 Apple Silicon 和 Intel 两种架构，无需另装依赖；仅使用本机临时文件传递通知，不另外上传内容。

同一配置面板新增 **工作日的工作时间内暂停飞书推送（可选）**，默认关闭，且**只有本机通知已开启时才生效**。本机通知关闭时，静默开关和时间输入不可用，飞书照常推送；已配置的静默规则保留，重新开启本机通知后才恢复生效。即使直接在 VS Code 设置中开启静默规则，也不能绕过本机通知的前置条件。开启后可自定北京时间的同日时段，例如 `08:30–18:00`：08:30 起暂停飞书任务完成／等待输入提醒，18:00 整恢复；本机通知独立运行，其他 Webhook 不受影响。静默期间的消息直接跳过，不会下班后补发；手动“测试远程推送”始终发送。

工作日按中国大陆法定节假日、调休判断：周末补班仍算工作日，平日放假不静默。启用后启动时检查日历，并在 VS Code 运行期间每小时检查是否到期；每个年度成功同步后 24 小时内不重复联网，失败一小时后重试，也可点“立即更新节假日与调休日历”。数据来自 [holiday-cn](https://github.com/NateScarlet/holiday-cn)（根据国务院公告维护，主源 GitHub，备用 jsDelivr），只请求公开年度 JSON，不发送项目或会话信息。

本地缓存最多使用七天；无有效缓存、数据未公布或无法确定工作日时，飞书照常推送。提前同步次年数据，12 月会结合次年元旦安排判断跨年调休；若次年数据未公布或失效，12 月暂不静默。面板显示当前年度的同步时间。日历按国家统一安排判断，不包含公司自定假期。直接在设置中配置可使用 `codexChat.notifyFeishuQuietHours`：`{"enabled":true,"start":"08:30","end":"18:00"}`；结束时间须晚于开始时间，非法配置不静默。

## 权限和回滚

| 模式 | 实际行为 |
| --- | --- |
| 按需审批 `default` | 只读沙箱；Codex 请求写入／额外权限时显示审批 |
| 自动编辑 `acceptEdits` | 允许工作区写入；额外权限仍需审批 |
| 只读 `plan` | 只读沙箱，不允许提权 |
| 完全访问 `bypassPermissions` | 不设沙箱限制，不请求审批；仅在明确需要时选择 |

修改权限、模型或推理强度对**下一轮**生效，不改变已经执行中的操作。Codex 的只读模式不是 Claude 的规划协议，不保证先展示计划再执行。

每轮发送前默认保存工作区中已打开的脏文件，再读取文本文件基线。快照单文件上限 2 MB，每轮总上限 64 MB，每个根目录最多扫描 20,000 个文件；跳过二进制、符号链接以及 `.git`、依赖、常见构建目录。`.DS_Store`、`Thumbs.db`、`desktop.ini` 等系统元数据默认忽略，不占扫描名额。工作区外路径没有自动回滚保障。快照不等同于 Git 备份；回滚前请确认自己的后续编辑是否要保留。

大型项目可在工作区设置中配置 `codexChat.snapshotExclude`，例如 `["coverage/**", "**/*.log"]`。规则相对于工作区根目录，`*` 匹配一层、`**` 可跨目录；排除路径不会纳入“已更改文件”及“还原到此处”的文件回滚。常规的二进制、大文件和符号链接跳过只写入“输出 → Codex Chat”，不再弹出逐项排除卡片；读取失败或扫描/容量上限只显示简短提醒，同一批问题在当前窗口内不重复提示。静默跳过不会永久排除项目资源，其实际变更仍会参与还原完整性检查。

历史版本点击“排除／排除全部”保存的本机记录继续生效，不创建或修改 `.vscode/settings.json`。可通过命令“Codex: 清除当前工作区的本机快照排除记录”恢复扫描。已有的 `codexChat.snapshotExclude` 配置仍然生效，不会自动删除或迁移。

原生历史由 `thread/read` / 分页接口读取，回退使用官方 `thread/fork`，旧会话归档作为恢复退路；用户主动删除使用官方归档后删除接口。插件不直接改写 Codex 的数据库或 JSONL。

其他入口创建的历史没有本插件文件快照，只能回退对话。终端代码块的“执行”按钮、外部程序的副作用，以及数据库／远程服务修改不属于文件回滚范围。

## 开发与验证

开发与打包需要 Node.js 22 或更新版本。

```bash
npm ci
npm run check-types
npm run build
npm test
npm run package
```

发布打包需在装有 Xcode 命令行工具的 macOS 上执行；`npm run package` 会先构建并本地签名双架构原生通知组件。

按 F5 启动扩展开发宿主。真实账号集成测试会发送简短模型请求、使用少量账号用量，并自动清理自己的测试会话：

```bash
npm run smoke
node scripts/smoke-process.cjs
npm run smoke:question
```

测试覆盖真实协议握手、登录读取、模型列表、对话、分页历史、派生、改名、删除，以及适配层真实工具审批、临时文件修改和续聊。自动测试另外覆盖错误处理、图片历史、回滚、消息与界面交互。`smoke:question` 使用 `gpt-6-astra`、medium 推理和绕过权限，分别验证新会话及恢复会话：问题展示前后端确认中断，在尚未回答时销毁并重建进程，恢复问题后等待 65 秒不执行工具，提交答案后才续轮写入测试文件。等待状态保存在插件存储目录，取消、回答或会话已续聊后会清除；私密回答在聊天历史中遮蔽。DOM 测试不替代 VS Code 中的视觉和快捷键验收。

日志位于 `~/.codex-chat/logs/`；命令面板“Codex: 打开日志文件夹”可直达。日志按本地日期轮转，只保留今天和此前六天；插件启动、跨天写入及运行期间每小时都会清理过期日志，目录中的其他文件不受影响。通知与提问日志记录会话 ID、阶段、结果和耗时，不记录对话或答案正文。插件快照保存在 VS Code 扩展全局存储中。

上下文压缩诊断写入同一份本机日志：`[compaction_prepare]` 记录手动压缩前的连接准备时间；`[compaction]` 记录手动／自动触发、模型、请求受理、服务端开始通知、重试、结束结果与耗时，等待期间每 30 秒记录一次。`elapsedMs` 是从插件请求（自动压缩则从开始通知）起算的时间，`serverElapsedMs` 从服务端开始通知起算，均不是服务端内部计算耗时。`preTokens` 为开始前最近上报用量；`latestTokens` 仅为压缩期间收到的用量，不能保证是压缩后值，未上报为 `null`。埋点不记录对话、工具输出或错误正文，不发送到外部统计服务，也不改变压缩阈值。排查时按日志中的会话、时间和压缩 `id` 关联阶段；请求受理不代表压缩完成。

`codexChat.transportDiagnostics` 默认开启，下次建立 Codex 连接时生效。它将该子进程的 OTel 日志和指标导出地址临时指向随机端口、随机路径的 `127.0.0.1` 采集器，不改写 `~/.codex/config.toml`；原来配置了自定义 OTel 导出的用户可关闭此设置以继续使用原导出地址。插件不启用被用户禁用的 `analytics`，因此指标可能不会上报。采集器仅将白名单字段写入 `[transport]`，丢弃提示词、工具输出、邮箱、账号信息、凭据、URL 查询参数和错误正文；监听失败不阻止聊天，进程关闭后释放监听。普通历史读取进程不开启此采集器。

新增字段与判断边界：

- `[compaction]`：`requestAcceptedMs`、`firstUsageMs`、`latestUsage`、结构化 `errorCategory` / `httpStatusCode`，以及本机管道收包计数与 `maxTimerDelayMs`。这些可帮助判断请求是否被受理、是否断流重试、扩展宿主是否长时间未调度；管道活跃不代表到 OpenAI 的网络正常，计时器延迟也可能来自系统休眠。
- `[transport]`：原生 HTTP 请求耗时、WebSocket 建连耗时及连接复用、`ttft_ms`、输入／缓存／输出 token 数。HTTP 耗时与首 token 时间包含多种等待，不能单独当成纯网络延迟或服务端排队时间。字段只在 CLI 实际提供时出现。
- `processRunId` 区分子进程；`sourceTimeMs` / `sourceTimeBasis` 保留事件发生时间及来源，`receivedAtMs` 是批量导出到达时间，两者差不能当作模型延迟。存在匹配的线程和源时间时，`compactionId` 可关联最近一次压缩；不确定时为 `null`，不会把迟到的导出归给新轮次。
- 后端可能提供 `responses_api_inference_time.duration_ms`、`responses_api_overhead.duration_ms` 与首 token／token 间隔指标。这些直方图明确标为 `process_aggregate`，保留统计起止时间、`count` / `sum` / `min` / `max` 和 `aggregationTemporality`，不能把多个请求的累计值当成单次压缩耗时。原生指标可能延迟导出；缺少上报不代表耗时为零。`serverQueueMs`、`networkTransitMs`、`inferenceMs` 在压缩摘要中保持 `null`，除非未来协议能给出可准确关联的证据；不做减法猜测归因。

当前已验证的 Codex CLI `0.162.1` 中，`thread/compact/start` 只有 `threadId`，没有独立的 `model` / `effort` / `serviceTier` 参数。手动压缩会先等待本会话速度设置保存，再通过 `thread/settings/update` 同步所选档位：普通明确传 `default`，快速传 `priority`，成功后记录 `settings_synced` 并开始压缩；同步失败则取消压缩，不沿用可能过期的收费档位。自动压缩沿用正在执行的轮次档位，运行中切换只影响后续操作。插件不会为压缩额外开启快速模式。诊断依据：[官方 App Server](https://learn.chatgpt.com/docs/app-server)、[官方 OTel 事件与指标说明](https://learn.chatgpt.com/docs/config-file/config-advanced)。

`codexChat.compactionMode` 默认 `balanced`：仅 **Astra 家族**的原生自动及手动压缩改用**已验证的 Sol + xhigh**。Sol、Luna（含后继版本）及未知家族都沿用会话模型与推理设置，不会因为压缩升级模型。层级按已知家族识别，不拿版本号当通用能力等级；模型目录目前没有通用等级分数。回答仍使用原会话配置，收费档位严格跟随该次原生请求。覆盖轮次开始前、工具执行后等 CLI 自动触发的位置，不额外触发真实会话压缩，不修改自动阈值。已接入的旧工具输入精简仍遵循下文保护与归档规则。选 `session` 可关闭优化；设置在下次连接生效。

压缩模型不固定在某一版本：`codexChat.compactionModel` 默认 `auto`，从连接时的 `model/list` 读取账号实际可用的 Sol 型号，优先参考官方 `upgrade` / `upgradeInfo` 关系发现候选。后继型号通过验证后，自动及手动压缩共用同一选择器采用较新的已验证版本。GPT-6.1-Sol 仅作为已有长历史评测的初始锚点；不会拼接出目录不存在的型号。也可指定某个 Sol ID，仍须验证且遵守层级约束；指定目标不可用或未验证时沿用会话。依据：[官方模型目录](https://learn.chatgpt.com/docs/app-server#models)、[官方模型选择说明](https://developers.openai.com/api/docs/guides/model-selection)。

`codexChat.compactionAutoValidate` 默认开启：完成至少一次用户操作并空闲 15 秒后，对新候选用隔离的临时线程和固定合成历史做原生压缩，再用同一个读取模型检查 16 个最新事实和 6 个操作判断。基线与候选均须 22/22，且候选压缩耗时不超过基线的 1.25 倍；小样本检查只能拦截明显退化，不能保证所有长历史无损或稳定提速。失败保留已验证旧版；旧版下线且无可用验证版本时沿用会话。

验证会额外消耗额度，但不读取真实会话，不启用快速档位，不提供工具，不阻塞正常操作；所有窗口每天合计最多领取一个候选，每个型号只自动尝试一次（失败、取消或崩溃不自动重试）。最多四个生成请求、12 个传输帧、768 KiB 累计请求体、180 秒；累计生成输出上限 44096 token，通常远低于上限。原生压缩要求 `max_output_tokens` 至少 20000，两个读取答案各限 2048；请求失败/重试同样扣减本机预算。验证元数据写入扩展全局存储的 `compaction-models`，不保存合成正文或凭据。关闭自动验证仍保留既有通过记录；新型号将在后续连接读取模型目录后发现。

`node scripts/build-test.cjs && node scripts/smoke-compaction-validation.cjs` 使用原生 CLI 和本机模拟上游检查通过、丢失事实拒绝、取消三个流程，不调用在线模型。2026-10-15 已用真实 GPT-6.1-Sol 分别充当基线和候选跑通该机制，两次均 22/22；这不是新旧型号的速度或质量比较，详见 [验证记录](benchmarks/compaction-policy-20261015.json)。

实现使用官方 `openai_base_url` 配置，为每个 CLI 连接创建固定上游的本机回环转发器，只识别 `/responses` 请求末尾的 `compaction_trigger`。普通回答按原字节转发，WebSocket、HTTP/SSE 继续使用原传输方式；转发器不自行重试模型或工具请求，重试仍由 CLI 管理。端口只监听 `127.0.0.1`，使用随机路径校验，不读取凭据文件、不将正文写入诊断日志、不更改全局配置。`[compaction_route]` 记录发送模型、档位和服务端返回模型；CLI 的 OTel `model` 仍可能是逻辑会话模型，不能独自作为压缩实际模型的依据。配置依据：[OpenAI 官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

压缩输入减量（自动和手动共用）：

- 对早于最近两个用户轮次、且不属于最近八个工具结果的纯文本长输出，保留开头、结尾和部分状态／错误行；完全相同的大段改为较新调用的引用。用户指令、回答、工具调用、调用 ID、图片和未知结构不做前置精简。最近范围只是本步骤的保护区，后续原生摘要仍可能压缩这些内容。
- 先将待精简的完整工具原文按内容哈希保存到 `~/.codex-chat/compaction-archive/<threadId>/`，摘录附带文件路径；目录权限 `0700`，文件 `0600`。每会话归档上限 64 MiB，不自动删除仍可能被摘要引用的文件。归档先写临时文件，完成后才发布到内容寻址路径，避免引用半份原文。同一次压缩的相同内容只保存／校验一次。归档失败、校验不符或容量不足时保留对应原文。归档保存的是工具输出，独立于不含正文的诊断日志；手动删除归档将失去这些恢复入口。
- WebSocket 的 `previous_response_id` 只有在本机确认完整前缀时才还原并精简，流式结果按 `output_index` 排序。缺项、重复序号、交错响应、steering、conversation、服务端压缩等无法可靠重建的状态保留原请求，不拼接猜测。改写后不再沿用旧响应引用；预热请求保持原样。普通回答不改写，取消或关闭连接后停止后续归档及转发。协议依据：[OpenAI 官方 WebSocket 说明](https://developers.openai.com/api/docs/guides/websocket-mode)。
- 同一轮连续三次自动压缩都没有新回复或工具结果，第四次开始时中断本轮并说明原因，避免无进展循环；正常输出或新一轮用户输入会重置计数。`session` 模式关闭这项保护及输入精简。
- 精简前预估减量，净收益必须同时达到 16 KiB 和原输入的 10%；不足时跳过归档与改写，避免为微小收益重发完整历史。精简准备设置 250 毫秒预算，到时保留原输入；未结束的文件操作收到取消信号，完成当前系统调用后不会继续处理其他片段。历史跟踪缓存不可变条目的序列化大小，增量续轮不反复序列化整个前缀。
- `[compaction_input]` 只记录输入前后字节数、归档及重复片段计数和保护区起点，不记录原文或路径。字节减量不等于 token 或耗时同比例下降；精简可能使部分前缀缓存失效。

仅接管已确认的官方默认提供方。自定义网关、未知账号、无法兼容的代理或账号缺少 Sol xhigh / 同收费档位时不改原生自动压缩。转发器遵循现有 HTTP(S) 代理环境；子进程具有不同代理设置时不接管。未接入转发时，手动压缩保留旧版临时切换模型、结束后恢复的兼容路径。连接关闭即释放转发器；恢复会话重新建立地址，关闭此优化后不沿用旧端口。

2026-10-15 使用同一份约 22.8 万 token 历史，在普通模式下复测：Sol xhigh 两次为 125 / 143 秒，压缩后统一由 Astra medium 回答预先固定问题，两次均通过 11 项事实和 5 项操作判断；同组 Astra xhigh 为 217 秒、11/11，Luna xhigh 为 30 / 38 秒、7/11 和 9/11。Sol medium 没有更快，Luna max 未稳定改善事实保留，因此默认选 Sol xhigh。连同此前相同历史的两次计时，Astra 三次平均为 198 秒，Sol xhigh 平均为 134 秒，观察到约 33% 的时间缩短。数据见 [基准摘要](benchmarks/compaction-20261015.json)。这是单一历史的小样本，检查通过不代表无损压缩或所有任务质量相同；耗时会受服务负载和缓存影响。

自动路径回归（2026-10-15）：用同源长历史，经插件真实 `CodexProcess` 发送普通消息，由 CLI 自行触发压缩，`thread/compact/start` 调用次数为 0；约 22.8 万 token，服务端确认压缩模型为 Sol，耗时 156.204 秒，随后 Astra medium 的 11 项事实和 5 项操作判断均通过。试验只在隔离线程降低阈值以触发自动压缩，生产阈值不变。该样本比前述手动基准多了短消息和插件指令，不能直接作为严格的自动提速 A/B。详情见 [自动压缩验证](benchmarks/auto-compaction-20261015.json)。`node scripts/build-test.cjs && node scripts/smoke-auto-compaction.cjs` 可运行本机模拟上游的原生 CLI 集成检查：工具返回 → 自动压缩 → 原模型继续，以及关闭转发后恢复；无需在线模型生成。

输入精简实测（2026-10-15）：同源历史、普通档位、原生自动压缩，实际压缩输入由约 22.9 万 token 降到 13.8 万，减少约 40%；两个优化样本耗时 119.420 / 110.611 秒，均通过 11 项事实和 5 项判断。同期关闭精简的对照为 104.014 秒、10/11 事实和 5/5 判断，前轮无精简样本为 156.204 秒。输入减量已证实，尚无稳定的墙钟提速证据，也不能据小样本声称质量全面提高。详见 [输入优化验证](benchmarks/context-optimization-20261015.json)。

本机回归（2026-10-15）：2 MiB 历史连续 80 次增量维护，三次测量的累计耗时中位数由 1462.51 毫秒降到 0.54 毫秒；64 段重复长输出的归档调用由 56 次降到 1 次。这里只测插件本机维护，不能当作模型或端到端压缩耗时。旧的 157 项真实历史样本在固定归档路径下生成的精简输入与上一版逐项一致，本轮未额外调用在线模型。可运行 `node scripts/build-test.cjs && node scripts/bench-compaction-local.cjs` 复测，数据见 [压缩检查记录](benchmarks/compaction-review-20261015.json)。

参考 Claude 的上下文管理：

- [Claude Code 官方机制](https://code.claude.com/docs/en/how-claude-code-works)先清理旧工具输出，必要时再摘要，并防止压缩后立即撑满造成无限循环。这能减少需要处理的历史量，但选择性清理也会失去旧细节。
- [Claude API 保留最近轮次](https://platform.claude.com/docs/en/build-with-claude/compaction-keep-recent-turns)让较旧轮次参与摘要、最近轮次原文保留，切点不能拆开工具调用与结果。
- [Claude API 后台压缩](https://platform.claude.com/docs/en/build-with-claude/compaction-background)在继续工作时压缩固定前缀，完成后保留期间新增的后缀；同时只运行一个压缩请求，失败保留原历史。它减少阻塞等待，但仍消耗请求与额度。

后两项是 API 编排方案，不能据此断言 Claude Code CLI 默认采用。本插件已借鉴旧工具输出精简、最近输入保护和无进展循环中止。后台压缩及压缩后保留原始最近轮次尚未实现：当前 [Codex CLI 0.162.1 源码](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/core/src/compact_remote_v2.rs) 的 `collect_compaction_output` 只接收单个压缩项，`build_v2_compacted_history` 自行重建历史；没有固定前缀与期间新增后缀的原子合并接口，不能通过附加响应条目可靠保留新内容。
